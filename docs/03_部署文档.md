## 1. 项目概览

面向跨境卖家的智能备货决策系统，核心链路：**数据归集 → 每日测算 → 备货建议 / 缺货滞销预警 / 采购计划 → 执行回写**。

单体仓库（monorepo）双进程：

- **后端** `backend/`：FastAPI 单层 API，进程内 APScheduler 定时测算。
- **前端** `frontend/`：React 18 + Vite SPA，`/api` 反向代理到后端。
- **数据库**：SQLite 单文件（默认）或 PostgreSQL（生产推荐）。

## 5. 本地开发部署

### 5.1 后端

```bash
cd backend

# 创建虚拟环境（推荐 uv；或 python -m venv .venv）
uv venv .venv --python 3.12
source .venv/Scripts/activate   # Windows；Linux/macOS 用 .venv/bin/activate

# 安装依赖（开发含测试：requirements-dev.txt；生产仅 requirements.txt）
uv pip install -r requirements-dev.txt
# 或：pip install -r requirements-dev.txt

# 初始化数据库（建表 + 迁移 + 导入 mock）
python -m alembic upgrade head
python -m app.core.seed --mock

# 启动（开发热重载）
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 5.2 前端

```bash
cd frontend
npm install
npm run dev          # 开发服务器 http://localhost:5173
```

### 5.3 验收

```bash
cd backend && pytest                                  # 27 个用例
cd .. && bash verify/stage0.sh … bash verify/stage7.sh # 分阶段验收门
bash verify/e2e.sh                                    # 全链路冒烟 + 生成验收报告.md
```

## 6. 生产部署（裸机 + Nginx + PostgreSQL）

### 6.1 数据库切换到 PostgreSQL

```bash
export DATABASE_URL="postgresql+psycopg://user:password@127.0.0.1:5432/stockwise"
# 需先安装驱动：pip install psycopg[binary]
cd backend
python -m alembic upgrade head
python -m app.core.seed --mock
```

### 6.2 后端与调度（systemd 双服务）

调度已拆分为独立进程（`app.scheduler_worker`），与 API 解耦，API 可放心开多 worker 而不会重复触发测算。

后端 API 服务 `/etc/systemd/system/stockwise.service`：

```ini
[Unit]
Description=StockWise Backend API
After=network.target

[Service]
WorkingDirectory=/opt/stockwise/backend
Environment=DATABASE_URL=postgresql+psycopg://user:password@127.0.0.1:5432/stockwise
ExecStart=/opt/stockwise/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 4
Restart=always

[Install]
WantedBy=multi-user.target
```

独立调度服务 `/etc/systemd/system/stockwise-scheduler.service`：

```ini
[Unit]
Description=StockWise Scheduler
After=network.target

[Service]
WorkingDirectory=/opt/stockwise/backend
Environment=DATABASE_URL=postgresql+psycopg://user:password@127.0.0.1:5432/stockwise
ExecStart=/opt/stockwise/.venv/bin/python -m app.scheduler_worker
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now stockwise stockwise-scheduler
```

### 6.3 前端（构建 + Nginx）

```bash
cd frontend && npm run build   # 产物在 frontend/dist
```

`/etc/nginx/conf.d/stockwise.conf`：

```nginx
server {
    listen 80;
    server_name stockwise.example.com;

    root /opt/stockwise/frontend/dist;
    index index.html;

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```bash
nginx -t && systemctl reload nginx
```

## 7. Docker 部署（推荐）

仓库已内置 `backend/Dockerfile`、`frontend/Dockerfile`、`frontend/nginx.conf`、`.dockerignore`、`docker-compose.yml`，一键拉起全套（PostgreSQL + 后端 API + 独立调度 + 前端 nginx）。

```bash
docker compose up -d --build
```

服务说明：

| 服务 | 镜像/命令 | 说明 |
|---|---|---|
| db | `postgres:16-alpine` | 数据持久化到 `pgdata` 卷，带健康检查 |
| backend | `backend/Dockerfile` | `alembic upgrade head && uvicorn`（1 worker） |
| scheduler | 同后端镜像，`python -m app.scheduler_worker` | 独立调度进程，每日 06:30 测算 + 预警，与 API 解耦 |
| frontend | `frontend/Dockerfile` 多阶段 | node 构建 → nginx 托管 + `/api` 反向代理 |

访问：前端 `http://localhost`，后端 `http://localhost:8000/api/health`。

## 8. 数据库迁移（Alembic）

```bash
cd backend
python -m alembic upgrade head       # 升级到最新
python -m alembic current            # 查看当前版本
python -m alembic revision --autogenerate -m "描述"  # 生成新迁移（模型变更后）
python -m alembic downgrade -1       # 回退一个版本
```

## 9. 定时任务（APScheduler）

- **独立调度进程** `python -m app.scheduler_worker`，默认每日 **06:30** 全量测算 + 预警扫描，与 API 进程解耦（避免多 worker 重复触发）。
- 环境变量覆盖：`CALC_CRON_HOUR`、`CALC_CRON_MINUTE`。
- 手动触发（开发/补跑）：`POST /api/calc/run`（API 内联执行测算 + 扫描，不依赖调度进程）。

## 10. 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DATABASE_URL` | `sqlite:///data/stockwise.db` | 数据库连接串；生产切 PostgreSQL |
| `CALC_CRON_HOUR` | `6` | 每日测算触发小时 |
| `CALC_CRON_MINUTE` | `30` | 每日测算触发分钟 |
| `DEEPSEEK_API_KEY` | 空 | DeepSeek API Key（AI 问答；不填则走规则兜底） |
| `DEEPSEEK_MODEL` | `deepseek-v4-flash` | DeepSeek 模型名 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com/v1` | DeepSeek API 地址 |

> 业务参数（权重/系数档位/阈值/备货周期/预算/大促日历）不走环境变量，统一存 `settings` 表，页面「系统设置 / 预警规则」可改。

## 12. 常见问题排查

| 现象 | 处理 |
|---|---|
| 前端 build 报 TS1484 | 类型导入需用 `import type { X }`（`verbatimModuleSyntax` 开启） |
| SQLite 锁 / 并发写入 | 生产改用 PostgreSQL，避免 SQLite 单写瓶颈 |
| 定时测算重复执行 | 多 worker 下调度需单进程承载；或仅 `--workers 1` |
| 导入 CSV 中文乱码 | CSV 需 UTF-8（带 BOM 亦可），适配器按 `utf-8-sig` 读取 |
| 远程推送 GitHub 失败 | 配置代理：`git config --global http.proxy http://127.0.0.1:7890` |
| 外部信号缺失 | 系统按「沿用上一期 + data_flags 标记」降级，不中断 |
